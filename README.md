# CarBiz

改裝零件的價格研究。目前一個題目：**BLITZ 為 Toyota GR86（ZN8）出的全產品線，日本定價 vs. 東南亞／香港當地售價。**

## 這是什麼

`blitz-gr86/index.html` 是一頁式靜態網頁，把 BLITZ 官方商品検索システム 對 GR86 / ZN8 / 2024 年式的查詢結果
（41 條產品線、110 個品項）整理成八個分類，列出日本含稅與稅拔定價，並附上各地當地售價的調查結果。

沒有框架、沒有 CDN、沒有 build step——直接用瀏覽器打開 `blitz-gr86/index.html` 就是成品。根目錄的 `index.html` 是站台首頁，
手寫的一頁清單，之後多一個題目就多一張卡片。

## 分類

懸吊・底盤 ／ 煞車 ／ 進氣 ／ 排氣 ／ 冷卻・油溫 ／ 電子・ECU・儀表 ／ 外觀空力 ／ 內裝・配件

分類是照「這個零件在車上做什麼」分的，不是照 BLITZ 官網的 category_id——官網那組 id 混了
產品線與用途兩種軸，直接沿用會出現同一顆東西掛在兩個地方。

## 重新產生

```bash
./scrape.py     # 重抓 BLITZ 官網 → data/blitz-gr86-zn8.json
./greycalc.py   # 水貨到岸試算 → 寫回 data/prices-local.json 的 grey 區塊
./build.py      # JSON (+ data/prices-local.json) → blitz-gr86/index.html
```

`greycalc.py` 裡面是**算式，不是抄來的數字**：日本出口通路實價＋實際運費報價＝CIF，再套各地關稅與稅金。
輸入來源與每一條稅制規則都寫在檔頭。之所以獨立成一支腳本，是為了讓頁面上的試算值可以被重新推導與稽核，
而不是手打進 JSON。

`scrape.py` 在解析出的品項數掉到 80 以下時會直接失敗退出。BLITZ 的表格不是每一列包一個
`.row`——一條產品線只開一個 `.row`，後面每一列都是平鋪的 `.td` 兄弟節點，所以用 `.row` 切會
只拿到 41 筆卻看起來完全正常。真正的列邊界是 `td td_model first`。

## 資料檔

| 檔案 | 內容 |
|---|---|
| `data/blitz-gr86-zn8.json` | BLITZ 日本官網原始品項（scrape.py 產生，不要手改） |
| `data/prices-local.json` | 泰國／馬來西亞／新加坡／香港當地售價與水貨試算（手動維護，可缺席） |

當地售價跟日本定價**同列**，一個國家一欄（泰、馬、新、港），用 BLITZ 的 code no. 對應——那是四個市場之間唯一
穩定的 SKU 鍵。分成一個獨立區塊會逼人捲動去比對這頁唯一存在的理由。

`prices-local.json` 是選擇性的：日本那份要在當地售價還沒查完時也能照樣出頁。整個國家缺席時
該欄顯示「調查中」，單一 SKU 沒查到就留白。格式：

```json
{
  "meta": { "rates": { "THB": 4.52, "HKD": 19.1, "MYR": 35.2 }, "asOf": "2026-08-29" },
  "countries": {
    "TH": { "summary": "一句話說當地通路長什麼樣",
            "channels": [ { "name": "店名", "url": "https://…", "kind": "官網", "note": "備註" } ],
            "notFound": [ "查不到公開標價的品項" ],
            "caveat": "查到價但無法安全對應料號、因此沒填進表的說明",
            "extra": [ "關稅與稅制", "運費與到岸試算", "法規限制…每則一段" ] }
  },
  "prices": {
    "92467": { "TH": { "amount": 72000, "url": "https://…", "seen": "2026-08-29", "kind": "新品" } }
  }
}
```

`countries` 裡有沒有那個國家，決定價格欄顯示什麼:**沒有那一國 = 顯示「調查中」，有那一國但該品項沒價 = 顯示「—」**。
這兩件事不一樣——一個是還沒查，一個是查過而當地沒有公開標價，混在一起會把未完成的欄位偷偷變成結論。

每個國家欄的格子裡有兩排：上排是查到的零售標價（`prices`），下排是水貨到岸試算（`grey`）。
兩者資料分開放，格式相同（`grey[料號][國碼] = { amount, kind, note }`），試算一律帶「試算」標記與計算式
（滑鼠移上去可看），永遠不會被誤讀成報價。

試算分兩級，格子上直接標明：**實報**是品項價與運費都來自實際報價（7 個料號），
**公式**是用 Black Hawk Japan 已驗證的定價比率加公告運費推算（其餘）。
頁面的前半是**查到零售標價**的品項，後半是只有試算的——分界是「有沒有人真的在賣」，不是有沒有數字。

`rates` 是**每 1 單位當地幣折多少日圓**。`amount` 給數字才會自動折算日圓與倍數；給字串
（例如「詢價」）就原樣顯示。`kind` 用來標新品／二手，馬來西亞的 half-cut 拆車件跟新品差距大，
混在一起會讓整張表失去意義。

## 價格口徑

日本價是**國內含稅定價**，括號欄為稅拔價，**不含**運費、關稅與當地稅。當地售價一律附來源
連結（點價格就開）與看到的日期；查不到公開標價的品項留白並列在「通路與稅費」那節，不做估算。
